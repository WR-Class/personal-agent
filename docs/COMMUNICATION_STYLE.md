# 沟通风格标准

每个需要用户拍板的决策点 = **5 段**，用大白话，不甩技术词。

## 5 段式

### 1. 做什么
**人话**描述这件事。不写变量名，不写实现细节。
- 什么输入、什么输出
- 用户视角看到啥变化

### 2. 为什么
- 这解决啥问题
- 不做的话会咋样

### 3. 代价
- 多少行代码 / 多少测试
- 多少风险（低 / 中 / 高）
- 多少时间

### 4. 替代选项
- 至少 1 个别的做法
- 各自的取舍

### 5. 推荐 + 理由
- 我推荐哪个
- 理由（不是技术理由，是产品 / 用户理由）

## 不用

- ❌ 变量名（dist / histWeight / OOV / margin / v5）
- ❌ 缩写（D-编号 / v3 v4 v5）
- ❌ 公式 / 数学符号（除非必要）
- ❌ 假装用户懂技术细节

## 用

- ✅ 比喻（"AI 状态 = 接力赛的交接棒"）
- ✅ 用户视角（"你会看到..."）
- ✅ 数字（"100 行代码" / "300 行测试"）
- ✅ 具体例子（"如果用户说'继续'，AI 会..."）

## 适用范围

- 任何 `do A 还是 B` 的拍板点
- 任何 `下一步做什么` 的提议
- 任何 `X 已完成，要不要继续 Y` 的回合
