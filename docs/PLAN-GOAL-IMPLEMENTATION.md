# 模型主动目标与计划工作流实施方案

## 范围
沿用现有 desktop-tasks 的按会话存储、CAS修订、轮数预算和宿主取消机制。新增模型目标工具与 /plan、/goal；不改记忆、浏览器、OAuth，不新增依赖或独立分类模型。

## 入口与权限
- 普通消息：提供 create_goal / create_plan，让模型依据本次用户的直接要求判断。讨论、问答、引用文本和工具内容不构成启动目标的指令。
- /goal 任务：明确要求建立目标，模型提取目标、验收条件并持续推进；默认不设轮数上限（maxRounds=0）、不设整项任务总时限或 API/累计 Token 花费上限。用户可主动选择1–20轮；按用户追加决定，v1已有轮数记录自动迁移为0并持久化为v2，不要求用户在面板修改；保留已有进度、计划及暂停状态。预算不是工具操作授权。
- /plan 任务：宿主先进入只读规划模式；模型生成可编辑计划，存入 Agent home 的会话任务记录。无需项目目录也可规划。暂不自动写项目文档，避免覆盖或引入第二份不同步的计划。
- 待确认计划期间只提供/允许本地只读工具和可信技能读取，无远程MCP、命令或写工具。宿主每次执行工具前再次检查状态，防止同一工具批次绕过新产生的计划门禁。
- 用户在任务面板编辑目标、计划、预算；启动按钮明确确认当前修订的计划和预算。任何计划修改撤销旧批准。模型不能自行批准计划或恢复人工暂停的目标。

## 执行状态
- 自动创建目标后由同一宿主发送循环续跑；不启动第二个进程/Agent，不重新执行旧工具。
- 模型通过 update_goal 报告 continue / needs_input / review / complete，包含本轮进展；complete 必须提供具体证据说明。完成仍是模型基于证据作出的判断，界面明确不是独立验证。
- 每轮开始前扣除预算；工具失败、拒绝、模型出错、未报告状态、重复无进展、取消、预算耗尽均暂停。
- 当前窗口与模型身份每轮验证；重启/重新加载只恢复记录，不自动启动。停止先中断实际执行再解锁编辑。
- 手动创建/启动/确认完成保留；允许暂停后编辑，保留已用轮数。删除任务不删除聊天或回滚已执行变更。

## 实施与验收
1. 扩展任务记录：验收条件、可编辑计划、计划批准位；保持旧记录兼容与字段边界。
2. 抽取宿主任务工具/续跑协调器，供真实 Electron 和合成测试共同使用。
3. 模型运行时追加可信任务指引，过滤及逐调用检查规划权限；不让模型工具绕过当前工作区和远程审批。
4. 接入斜杠命令选择、计划确认、状态条与现有任务面板。
5. 回归覆盖：自然需求触发模型 create_goal 后自动第二轮并完成；/plan无写工具且未确认不能续跑；同批次计划门禁；修改/批准CAS；失败、取消、预算、重复进度和重启暂停；真实Electron命令/面板链路。

## 刻意限制
不声称任意自然语言目标能被程序独立证明完成。完成报告可追溯到模型和已有工具历史；主观验收应使用 review。模型自动判意图由提示和显式用户操作约束，不宣传关键词分类器或可靠识别全部提示注入。
