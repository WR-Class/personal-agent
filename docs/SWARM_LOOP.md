# 蜂群本地闭环：设计基线与缺口清单

本文件是"本地闭环"的**验收基线**，用于避免再次出现"单点功能已实现，但整体闭环被误认为已完成"。

目标链路：

```
用户输入
  → TaskSpec（任务契约）
  → 基因选择
  → PDRI 执行周期（Plan → Do → Review → Integrate）
  → 结果评估
  → 能力沉淀
```

维护规则：每完成一个环节，更新该环节的**当前状态**与**验收条件**；只改受影响的章节，不回写其他文档的历史批次。

对照与取舍见 [REFERENCE_DECISIONS](REFERENCE_DECISIONS.md) D12（TaskSpec）、D13（扇出工具撤回）、D14（蜂群 = 基因库 + RSI 闭环）；代码位置见 [CODE_MAP](CODE_MAP.md)。

---

## 1. 一句话结论

**阶段 A 的骨架已贯通**：TaskSpec、基因定义/存储/选择、**PDRI 周期（显式状态机 + 周期账本）**、**机械评估**、**结果回灌选择** 均已落地并有端到端测试。仍缺的是"更聪明的部分"：独立评审角色、失败蒸馏（distill）、成功归纳（induct）、基因版本/血缘，以及写入门那一片的文件与行数硬预算。

因此当前可以称为：

> TaskSpec → 基因选择 → PDRI 四阶段 → 机械评估 → outcome/gene-less 基线 → 选择器消费历史

还不能称为：

> 具备蒸馏与归纳的自进化蜂群（多角色评审、变异、跨机交换）

**已经可执行的一条测试证明反馈真的闭环**（`test/cycle.test.ts`）：一轮失败被记账后，**下一轮的基因选择确实改变**——失败基因被扣分直至被隔离，另一个候选被选中并成功。

## 3. 逐环节：最终形态与验收条件

### 3.1 TaskSpec

**定位**：后续所有环节共用的任务契约。它明确"这一次要做什么"，不负责执行，也不判定成功。

最终形态：目标 + 意图 + 信号 + 约束 + 风险 + 预算 + 验收条件 + 版本。

验收条件：

- 相同输入得到稳定、可解释的 spec；
- 可被基因选择直接消费（intent 门控、signals 打分）；
- 执行与评估引用同一份 spec（同一 `runId`）；
- 缺目标、约束冲突时可在执行前拒绝，且拒绝**不留痕迹**；
- 硬拒发生在任何写入与模型调用之前。

### 3.2 基因选择

最终形态：候选过滤 → 候选评分（信号匹配、约束匹配、历史成功率、新近度、失败惩罚、探索因子）→ 选择结果（选中基因、候选列表、分数、理由、策略版本）。

验收条件：

- 同一 spec 能列出候选并解释排序；
- 选择理由与候选分数落盘可复查；
- 历史结果影响后续排序；
- 无匹配时明确返回"无基因"，**不伪造选择**；
- 连续失败的基因被降权或隔离。

### 3.3 PDRI 执行

PDRI 是纪律层，不等于"多开几个子 Agent"。

- **Plan**：确认 spec 与选中基因、分解步骤、明确工具与权限、明确预算/超时/取消条件、明确本轮验收标准。
- **Do**：按计划执行模型与工具调用，记录步骤、输入、输出与错误，遵守 M2 边界。
- **Review**：检查目标是否完成、约束是否满足、是否越权、是否需要重试或终止，产出结构化评估。
- **Integrate**：合并结果、写入周期结论、触发能力沉淀、把评估反馈给基因库。

最终形态：每次任务一个显式周期对象，含 `cycleId`、`taskSpec`、选中基因、计划、步骤、工具事件、审查、整合、状态、时间戳。状态只按规则流转：

```
planned → executing → reviewing → integrating → completed
executing/reviewing → failed | blocked | cancelled
```

验收条件：

- 每次任务有唯一周期 ID；
- 四个阶段各有输入、输出与结束原因；
- 取消、超时、失败都能明确收口（含被取代的悬空周期）；
- Review 未通过时**不能**标记完成；
- 只有 Integrate 完成后才进入能力沉淀；
- **写入受每周期账本约束**：超预算的写入在执行前被拒，被拒的写入不留痕（无半写文件、无悬空工具关联），拒绝记入 `audit`；选中基因的 constraints 就是本轮预算。

### 3.4 结果评估

最终形态：

```
Evaluation
  ├─ status: success | partial | failed | blocked
  ├─ objectiveSatisfied
  ├─ constraintsSatisfied
  ├─ evidence[]            ← 含 validation:<outcome>=<claim> 逐条结果
  ├─ failureClass
  ├─ confidence
  ├─ reviewer
  ├─ retryRecommendation
  └─ notes
```

**已落地的部分（D20）**：`constraintsSatisfied` 有了机械依据——基因的 `validation` 声明逐条比对写入账本与工具序列，三态 `met/unmet/unverifiable`；被推翻的声明使本轮降为 `partial`；`satisfied` 只在全部 `met` 时为真。**`objectiveSatisfied` 仍然故意不存在**：没有任何机械依据能判断"目标是否达成"，加一个字段就是编造。

评估优先使用客观证据：测试是否通过、文件是否存在、工具是否返回成功、输出是否符合 schema、是否越权、是否超预算、是否满足 spec 验收条件。

**当前最重要的缺口（D19/D20）**：上面这一串里，"验证通过"这一项**只有半机械形态**——声明与比对已经落地（`Gene.validation` 是结构化声明，轮末按日志事实逐条比对，三态 `met/unmet/unverifiable`），但 **`command` 声明无法执行**（无 shell），一律记为 `unverifiable`。所以系统现在已经能抓出"基因过度声明"（声明与事实不符 → 降为 `partial`），但还不能证明"测试真的通过了"。**这一半是有意为之，不许假装它是真的执行**；M3 进程工具落地后才补上另一半，那之后独立评审者与增益定价才具备前置条件。

验收条件：

- 每个周期都有 Evaluation；
- **不依赖模型自报成功**；
- 失败原因可分类；
- 结果可直接更新基因统计；
- 低置信度结果可进入人工复核。

### 3.5 能力沉淀

能力沉淀不等于保存整段对话，而是提取可复用的结构化经验。

最终形态：每周期产出 Outcome（`cycleId`、spec 指纹、选中基因、状态、证据、失败分类、耗时、成本、时间戳）；长期汇总为 GeneStats（`address`、尝试数、成功/部分/失败/阻塞数、成功率、置信度、适用信号、失败模式、最后使用时间）。

验收条件：

- 每次结果关联到基因（或无基因基线）；
- 成败都更新统计；
- **失败不会被沉淀成"成功能力"**；
- 新能力有来源、证据与版本，且经过操作者准入；
- 后续选择消费沉淀结果；
- 可追溯某基因由哪些周期产生。

## 4. 与阶段矩阵的关系

| 归属 | 负责内容 |
|---|---|
| M2 权限与受控修改（已收口） | 工具权限、路径保护、写入批准、env 隔离、预算、超时、取消、审计、失败不越权 |
| 蜂群本地闭环（本文件） | TaskSpec、基因库、基因选择、PDRI、结果评估、失败记忆、能力沉淀、历史反馈、基因进化 |
| M6 多 Agent（未开始） | fork、任务调度、并发文件冲突管理、跨 Agent 合并 |

蜂群闭环建立在 M2 之上：基因只能影响**提示与策略**，不能绕过工具权限与批准。M2 收口不等于闭环完成，闭环完成也不等于 M6 多 Agent 完成。

**扇出执行明确后置**：参考 EvoMap 的实验数据（原子拆分 + 隔离上下文 + 程序汇合 70.7%，主从模式仅 38.5%，转述链路丢失 166 个已判对的答案），将来实现扇出时必须是"程序合并、绝不文本回传再综述"，且届时才引入并发（见 D13/D14）。

## 6. 实施顺序

### 阶段 A：最小可运行闭环（当前最近一步）

```
TaskSpec → 选择基因 → PDRI 四阶段 → Review → Outcome → 更新基础统计
```

要求：单任务、少量候选、本地存储、显式状态、可审计、可测试、**不自动修改核心能力**。

### 阶段 B：反馈闭环

历史成功率、失败分类与失败记忆、选择理由留档、重新选择、重试与降级建议。

### 阶段 C：能力蒸馏

从重复成功提炼候选基因、从重复失败提炼限制条件、基因版本与血缘、操作者批准后入库。

### 阶段 D：进化优化

探索/利用、基因组合、价值定价、自动降权与淘汰、更复杂的群体协作、（可选）外部能力交换。

**顺序理由**：先把"能进化的骨架"做通，再让它变聪明。跳过 A 直接做 D 会导致无法判断某基因是否真的有效、失败发生在哪一阶段、所谓"群体智慧"是否只是多次调用模型。

## 7. 端到端验收

只有同时满足下列条件，才可宣布本地闭环完成：

**任务契约**：输入生成带版本与指纹的 TaskSpec；约束进入执行流程。
**基因选择**：候选可查、选择可解释、结果被记录、无匹配安全退出。
**PDRI**：周期唯一 ID；四阶段均有记录；异常可收口；取消/超时/失败状态明确。
**结果评估**：每周期都有 Evaluation；含客观证据；四态可分；失败可分类。
**能力沉淀**：Outcome 落盘；基因统计更新；失败经验可查；新能力有来源与证据；后续选择消费历史结果。
**安全治理**：工具调用仍受 M2 约束；沉淀不绕过批准；失败不伪造成功；日志不泄漏敏感信息；周期状态与审计一致。

最终还需一条端到端测试证明反馈真的闭环：

```
输入 → TaskSpec → 选择基因 → PDRI → Review → Outcome → GeneStats → 下一次选择发生变化
```

**在这条测试通过之前，不实现自动基因生成、复杂多 Agent 调度与外部能力传播。**
