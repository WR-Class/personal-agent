# 这个 Agent 现在能做什么

更新：2026-09-28。这份文件只回答三个问题：**现在能做什么、现在不能做什么、跟成熟产品差在哪。**
不记录设计讨论；那些在 [STATUS](STATUS.md) 与 [REFERENCE_DECISIONS](REFERENCE_DECISIONS.md) 里。

一句话：**它能读写工作区里的文件、能跑命令、能自己验证改对了没有，并且在动手前问你。**

---

## 1. 现在能直接用的

| 能做什么 | 怎么用 | 验证状态 |
|---|---|---|
| 读工作区文件 | `read_file` | 已测；二进制会返回十六进制转储，不是乱码 |
| 检查二进制/可执行文件 | `inspect_file`（受审计的只读工具；本机实测可用 `certutil`、`findstr`） | 真机通过：读出 PE32+ / AMD64 / 签名者 |
| **跑任意命令** | `run_command` | **真机通过**：写完脚本→运行→拿到真实输出 |
| 读工作区外的文件 | `--trust-root <目录>` 先授权 | 真机通过：未授权时拒绝，授权后可读 |
| 改文件（改/补/建/删/改名/批量） | 六个文件工具，**逐次问你** | 已测；批准后文件若被改过会拒绝写入 |
| 自己验证改对了没有 | 跑测试/编译，看真实输出 | 真机通过（这是 `run_command` 最大的意义） |
| 三档权限 | `--tier read-only \| workspace-write \| full-access` | 三档行为已逐档实测 |
| 自测（真机） | `npm run test:live` | **7/7 通过**（无凭据时如实报"未测量"，不报绿） |
| 交互命令行 | `npm.cmd start` | 你已验收过 |

## 2. 现在不能做的

**按"会不会挡路"排序，不按好听程度：**

| 不能做什么 | 什么感受 |
|---|---|
| **长时间任务** | 命令 2 分钟超时**直接杀掉**，没有后台作业。实测已撞到：让它写 FizzBuzz 第一次就超了总时限 |
| **同时干几件事** | 单线程，一次一个任务 |
| **子任务 / 多 Agent** | 没有 |
| **Skill / 插件** | 没有 |
| **桌面界面** | 只有命令行 |
| 记忆 | 没有跨会话长期记忆 |
| 操作系统级隔离 | **没有，而且设计上就不假装有**（见下） |

## 3. 跟成熟产品对比

**对比的 9 个产品都是真实源码读过的**，源码在 `_research/repos/`（**注意：它在 git 仓库之外，未纳入版本控制**，见 [REFERENCE_DECISIONS](REFERENCE_DECISIONS.md) 开头的说明）。

### 3.1 权限档位 —— 对齐了

| | 档位 |
|---|---|
| **本项目** | `read-only` / `workspace-write` / `full-access` |
| **DSH**（你现在用的） | 仅可查看 / 工作区内修改 / 完全权限 |
| **Trae** | 手动审批 / 自动审批 / 完全访问 |
| **goose** | `Chat` / `Approve` / `SmartApprove` / `Auto` |
| **codex** | 沙箱档 `read-only`/`workspace-write`/`danger-full-access` × 审批档 `untrusted`/`on-request`/`granular` |
| **claude-code** | `default`/`acceptEdits`/`plan`/`dontAsk`/`auto`/`bypassPermissions` |
| **gemini-cli / qwen-code** | `default` / `yolo` |

**差距**：本项目**没有中间档**（goose 的 `SmartApprove`：只问敏感的）。本项目的 `workspace-write` 是"**每一条写入都问**"，问得比它们多。

### 3.2 手脚 —— 对齐了

| 能力 | 本项目 | 成熟产品 |
|---|---|---|
| 跑命令 | ✅ `run_command` | ✅ 全都有（crush 的 `bash`、codex 的 `run_command`…） |
| 命令形式 | 一个字符串，经平台 shell | 同 |
| 输出上限 | ✅ 64KB | crush 30KB |
| 超时 | ✅ 120 秒**杀掉** | crush **60 秒转后台** ⚠️ |
| 后台作业 | ❌ | ✅ `job_output` / `job_kill` ⚠️ |
| 读/写/搜索文件 | ✅ | ✅ |

### 3.3 安全边界 —— **这里要诚实**

**成熟产品的安全靠什么（源码读到的）：**

- **codex**：靠**真沙箱**（macOS Seatbelt 等），**Windows 上上游原版没有沙箱**
- **goose**：**取消过 macOS 沙箱**，转回审批档
- **crush**：靠 **fail-closed**（没命中免问清单就弹窗）

**本项目靠什么，以及不是什么：**

| 本项目有的 | 本项目**没有**的 |
|---|---|
| 路径收敛（读写都在工作区内，可授权外部只读） | 操作系统级隔离 |
| 写入预算（每轮最多几个文件、几行） | 网络限制 |
| 子进程环境白名单（`HOME` 指向 agent 自己的家，不是你的） | 文件锁 / 防竞态 |
| 有界输出 + 审计 | 防恶意代码（跑起来的程序想干什么就能干什么） |

**一句话：本项目是"收敛 + 审计 + 询问"，不是"隔离"。** 这点写在 [SAFETY](SAFETY.md) 里逐条列了。

## 4. 跟"要能用"还差什么

**按挡路的程度排：**

1. **后台作业** —— 现在长任务直接被杀，等于只能干短活。成熟产品都有。
2. **中间档** —— 现在每条写入都问，会很烦；goose 的 `SmartApprove` 是现成参考。
3. **多 Agent** —— 你说的"最终多 Agent"，还没开始。
