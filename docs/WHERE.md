# 这个 Agent 现在能做什么

更新：2026-09-28。这份文件只回答三个问题：**现在能做什么、现在不能做什么、跟成熟产品差在哪。**
不记录设计讨论；那些在 [STATUS](STATUS.md) 与 [REFERENCE_DECISIONS](REFERENCE_DECISIONS.md) 里。

一句话：**它能读写工作区里的文件、能跑命令、能自己验证改对了没有，并且在动手前问你。**

---

## 1. 现在能直接用的

| 能做什么 | 怎么用 | 验证状态 |
|---|---|---|
| 读工作区文件 | `read_file` | 已测；二进制会返回十六进制转储，不是乱码 |
| 检查二进制/可执行文件 | `inspect_file`（受审计的只读工具；本机实测可用 `certutil`、`findstr`） | 真机通过：读出 PE32+ / AMD64 / 签名者 |
| **跑任意命令** | `run_command` | **真机通过**：写完脚本→运行→拿到真实输出 |
| **长时间命令转后台** | `run_command` 的 `run_in_background`，配 `job_output` 读输出、`job_kill` 停 | **真机通过**：模型自己启动→读输出→停掉，三轮全绿 |
| 读工作区外的文件 | `--trust-root <目录>` 先授权 | 真机通过：未授权时拒绝，授权后可读 |
| 改文件（改/补/建/删/改名/批量） | 六个文件工具，**逐次问你** | 已测；批准后文件若被改过会拒绝写入 |
| 自己验证改对了没有 | 跑测试/编译，看真实输出 | 真机通过（这是 `run_command` 最大的意义） |
| **四档权限** | `--tier read-only \| ask-before-writing \| workspace-write \| full-access` | **四档行为已逐档实测** |
| **只读命令免问** | `ask-before-writing` 档：`ls`、`cat`、`grep`、`dir`、`node --version` 等不再逐次问 | **真机通过**：只读命令跑通、写命令仍被拦 |
| 自测（真机） | `npm run test:live` | **8/8 通过**（无凭据时如实报"未测量"，不报绿） |
| 交互命令行 | `npm.cmd start` | 你已验收过 |

## 3. 跟成熟产品对比

**对比的 9 个产品都是真实源码读过的**，源码在 `_research/repos/`（**注意：它在 git 仓库之外，未纳入版本控制**，见 [REFERENCE_DECISIONS](REFERENCE_DECISIONS.md) 开头的说明）。

### 3.1 权限档位 —— 对齐了

| | 档位 |
|---|---|
| **本项目** | `read-only` / **`ask-before-writing`** / `workspace-write`（默认） / `full-access` |
| **DSH**（你现在用的） | 仅可查看 / 工作区内修改 / 完全权限 |
| **Trae** | 手动审批 / 自动审批 / 完全访问 |
| **goose** | `Chat` / `Approve` / `SmartApprove` / `Auto` |
| **codex** | 沙箱档 `read-only`/`workspace-write`/`danger-full-access` × 审批档 `untrusted`/`on-request`/`granular` |
| **claude-code** | `default`/`acceptEdits`/`plan`/`dontAsk`/`auto`/`bypassPermissions` |
| **gemini-cli / qwen-code** | `default` / `yolo` |

**中间档 `ask-before-writing` 是本轮新加的**，对标 goose 的 `SmartApprove`（只问敏感的）。

**但我们和 goose 的判定方式不同，而且这个差别是刻意的：**

| | goose `SmartApprove` | 本项目 `ask-before-writing` |
|---|---|---|
| 怎么判"只读" | **调一次模型**去判断（`permission_judge.rs`） | **查已知事实**：命令的第一个词/子命令 |
| 判定失败时 | 返回空集 = 全部都要问（fail-closed，对的） | 未识别 = 要问（fail-closed） |
| 代价 | 每次判定**多一次模型调用** | **零额外调用** |

**为什么不用模型判**：goose 的工具来自 MCP，是外部来的，它**无从知道**某个工具是否只读，只能问模型。而**本项目的工具全是我们自己写的** —— 哪些只读是代码里的静态事实（`READ_ONLY_TOOLS`）。**把已知事实拿去让模型猜**，等于平白加一次网络往返和一个不可预测的失败点。这跟之前拒绝 `chars/4` 估算 token 是同一个理由：**宁可说"不知道"，也不用一个可能双向都错的推断。**

**代价说清楚**：白名单很短，`git` **整族都要问**（原因见下），`npm test`、`node build.js` 这类也要问。**漏判只会多问一次，不会少问一次** —— 这是可以接受的失败方向。

**⚠️ 这里修掉过一个真实漏洞，记下来当教训**：中间档**先发布过一版**把 `git status`/`log`/`diff` 判为只读免问。**实测推翻了它**：仓库自己的 `.git/config` 里设 `core.fsmonitor`，然后运行 `git status` —— **那条命令被执行了，文件被写出来了**。也就是说，一条被本档位判为"只读、不必问"的命令，执行了仓库自带的任意代码。

- **为什么不能小修**：`GIT_CONFIG_NOSYSTEM` **只关系统级配置，关不掉仓库级**；逐个危险键用 `git -c` 覆盖，等于要枚举 `fsmonitor`/`pager`/`textconv`/`sshCommand`/`hooksPath`/`filter.*`/`alias.*`…——**这正是本项目已经栽过两次的"枚举危险项"套路**。
- **现在的处置**：`git` 整族移出白名单，一律要问。**代价是真实的**：`git status` 现在会打断你一次。
- **同类被移出的还有**：`rg`（有 `--pre` 执行外部命令；本机没装，无法核实）、`npm ls`（读项目 `.npmrc`，未验证）。
- **提炼出的准入准则**：一个工具能进白名单，**当且仅当它自己的标志、和它读取的任何项目本地配置，都不能让它去执行另一个程序**。
- **已固化为回归测试**：建真实投毒仓库，**先在 `full-access` 下证明它真会执行**（反证，防止测试空过），再断言中间档下**不执行**。

**要恢复 `git` 免问，得先做 D26（仓库自带配置不得自行提权）** —— 见下面第 4 条。

### 3.2 手脚 —— 对齐了

| 能力 | 本项目 | 成熟产品 |
|---|---|---|
| 跑命令 | ✅ `run_command` | ✅ 全都有（crush 的 `bash`、codex 的 `run_command`…） |
| 命令形式 | 一个字符串，经平台 shell | 同 |
| 输出上限 | ✅ 64KB | crush 30KB |
| 后台作业 | ✅ `run_in_background` / `job_output` / `job_kill` | ✅ 同形状 |
| 超时 | ✅ 120 秒 | crush 60 秒 |
| 超时的处置 | ✅ **转后台**（照 crush） | crush 转后台 |
| 后台输出落盘 | ✅ agent home 下，7 天 / 256MB 自动清理 | crush 同形状（`spillRetention` / `spillDirLimit`） |
| 退出即清理 | ✅ 关掉 agent 就停掉所有后台作业 | crush **不清理**（作业活过 agent）⚠️ |

**最后一行是我们比 crush 严的地方**，也是你选的（A）：**"忘了还有东西在跑"是最难发现的问题**，所以关掉就是关掉。

### 3.3 安全边界 —— **这里要诚实**

**成熟产品的安全靠什么（源码读到的）：**

- **codex**：靠**真沙箱**（macOS Seatbelt 等），**Windows 上上游原版没有沙箱**
- **goose**：**取消过 macOS 沙箱**，转回审批档
- **crush**：靠 **fail-closed**（没命中免问清单就弹窗）

**本项目靠什么，以及不是什么：**

| 本项目有的 | 本项目**没有**的 |
|---|---|
| 路径收敛（读写都在工作区内，可授权外部只读） | 操作系统级隔离 |
| 写入预算（每轮最多几个文件、几行） | 网络限制 |
| 子进程环境白名单（`HOME` 指向 agent 自己的家，不是你的） | 文件锁 / 防竞态 |
| 有界输出 + 审计 | 防恶意代码（跑起来的程序想干什么就能干什么） |

**一句话：本项目是"收敛 + 审计 + 询问"，不是"隔离"。** 这点写在 [SAFETY](SAFETY.md) 里逐条列了。

## 4. 跟"要能用"还差什么

**已补上的（本轮之前排的队）：**

- ~~**后台作业**~~ → ✅ 已做（`run_in_background` / `job_output` / `job_kill`，退出即清理）
- ~~**中间档**~~ → ✅ 已做（`ask-before-writing`，只读命令免问）

**还差的，按挡路程度排：**

1. **多 Agent / 子任务** —— 你说的"最终多 Agent"，还没开始。这是最大的一块。
2. **Skill / 插件** —— 没有扩展机制，能力写死在代码里。
3. **中间档的覆盖面** —— 白名单很短：`git` 整族、`npm test`、`node build.js`、`rg` 都**仍然会问**。要再少问，就得回答"这个命令/脚本安全吗"，而那需要沙箱，我们没有。**其中 `git` 是最疼的一条**（`git status` 每次都要批准），而它疼是有原因的：见 3.1 的漏洞记录。
4. **配置文件加载 × 规则表（D26）** —— "仓库里的配置不能自己给自己提权"，**还没实现**。原本这条只是"将来支持读仓库配置时才需要"，**现在它已经在挡路了**：`git` 之所以不能免问，正是因为仓库自带的 `.git/config` 能让一条只读命令执行任意代码，而我们没有机制压住它。**做了 D26 才能把 `git status` 这类还回来。**
